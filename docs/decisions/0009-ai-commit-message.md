# 0009 AI 生成提交信息

日期:2026-11-05 · 状态:已采纳

## 背景

参考业界(GitHub Copilot、JetBrains AI、Cursor)的做法:在设置里配置模型,提交框里一个按钮,
按待提交的改动生成提交信息。

## 决定

- **协议**:只支持两类——OpenAI 兼容(`/chat/completions`,覆盖 OpenAI、DeepSeek、通义、Ollama、中转)
  与 Anthropic(`/v1/messages`)。地址、模型留空时用协议默认值;本机地址不要求 Key。
- **联网**:走系统 `curl`,与更新、头像同一思路,不引入 HTTP / TLS 依赖。请求体放临时文件,
  请求头(含 Key)经 stdin 的 curl 配置交给它,不出现在命令行参数里,`ps` 看不到。
- **材料**:`gitcore::change_context` 用 git2 读已暂存的补丁(一个文件都没暂存时退回工作区已跟踪改动),
  整体上限 24 KB、单文件 8 KB,超出的截断并在提示词里说明;再带最近 5 条提交标题让生成的信息沿用仓库写法。
- **提示词可配**:格式(Conventional Commits / 一行 / 摘要加要点)、语言(中 / 英)、附加要求。
- **API Key** 目前明文存在设置文件里(设置页已写明)。个人自用、文件在用户目录下;
  需要时再改成存 macOS 钥匙串(`security` 命令),接口不变。
- **隐私**:diff 会发给用户填的接口;设置页顶部有提示。默认不配置就不联网。
- 结果覆盖提交框当前内容;生成期间按钮转圈,重复点击无效。

## 不做

- 流式输出、多候选、自动提交:先把“一键填入、自己改”做稳。
- 测试连接按钮:直接用 ✦ 即可验证,失败原因会原样提示。
