# 0008 fork gpui-component 的 diff 模块

日期:2026-11-05 · 状态:已采纳(在 0007 的基础上)

## 背景

0007 改用了 gpui-component 的 `Diff`,但它的布局不能满足“像编辑器的对比视图”:
并排时左右两栏铺在同一个横向滚动面上,每栏宽度取全文件最长行,长行会把新版本那一栏挤出屏幕。
这类问题在它的渲染代码里,只靠公开接口改不了。

目标(验收标准):

1. 并排时左右各占半屏,各自裁剪、共用横向滚动偏移,上下同步,不换行;
2. 显示完整文件,未改动的大段折叠,可展开;
3. 拖选、双击选词、⌘A、⌘C 自然可用;
4. 上一处 / 下一处改动快捷键,滚动条旁标出改动位置;
5. 配色克制:整行浅底,只在改动不多的代码行加深改动字符。

## 决定

- 把 gpui-component 0.9.0 的 `src/diff/`(Apache-2.0)复制成独立 crate `crates/diffview`,保留许可证文件;
  `ui` 依赖它,不再用 `gpui::component::diff`。
- 改动最小化、保持上游结构,便于对照;本项目“单文件 ≤ 300 行”的规则不适用于 fork 代码。
- 已做:界面文字换成中文(`i18n.rs`);去掉内置 tree-sitter 高亮路径(我们总是注入 syntect);
  按键上下文改名为 `GitlaneDiff`、动作命名空间改为 `gitlane_diff`,避免与原版快捷键冲突。
- 不换行时按编辑器的方式布局(`lib.rs` 里标了“Gitlane 改动”):每栏宽度跟可视区,并排各占一半;
  行号栏固定,代码在栏内裁剪、按共享的横向偏移平移。外层滚动容器只用来记录偏移和可滚范围
  (列表加宽 `scroll_range`、再右移 `scroll_x` 抵消外层平移)。选区按同一个偏移换算,不受影响。
  统一视图同样处理,横向滚动时行号不再被带走。测试见 `layout_tests.rs`;
- 显示完整文件(标准 2):`gitcore::diff::display_diff` 用极大的上下文(`FULL_CONTEXT`)把同一个文件重读一遍,
  整个文件成为一个 hunk,组件按设置里的上下文行数折叠未改动区域,点折叠行展开。暂存仍用按设置上下文读的那份 diff
  (hunk 划分不变),两份行号一致,选区按 (类型, 旧行号, 新行号) 换算回暂存 diff。
  文件超过 `FULL_DISPLAY_MAX_LINES` 行时退回只显示暂存那份。相邻 hunk 间没有隐藏行时不出分隔行。
- 改动导航与标记(标准 4):`F7` / `⇧F7`(也可 `⌥↓` / `⌥↑`)跳到下一处 / 上一处改动,diff 获得焦点时生效;
  滚动条旁画一条 4 像素宽的改动标记,位置与高度按显示行占比算(折叠后的行也算一行)。
- 配色(标准 5):`DiffPalette`(`ui/colors.rs` 的 `diff_palette`)提供浅粉 / 浅绿整行底色;
  行内强调改按字符比较,且仅在相似度 ≥ 0.6、改动片段 ≤ 4 段的行上出现,否则只有整行底色。
- 新增直接依赖 `smallvec`、`unicode-segmentation`、`unicode-width`:上游模块原本就用,
  已在依赖树里(gpui-component 的依赖),不引入新下载。
- 上游的单元测试依赖 gpui-component 内部的测试设施,没有搬过来;改动处补本 crate 自己的测试。

## 代价

- 约 7000 行代码由我们维护。gpui 版本本来固定(0002),不存在跟随上游的问题。
