### 已定位的性能问题

- **已修复:扫描对话框点复选框卡顿**。任何一次 `notify` 都会重绘整个窗口,而左侧引用树当时把所有引用一次性渲染
  (`bw-go` 有 1,033 个)。改为 `uniform_list` 后只渲染可见的约 30 行。同时修复:编辑器后台 `git status`
  刷新 `.git/index` 被当成引用变化触发全量重载(每次约 1 s,还会并发多份),现在 index 变化只刷新 status,
  且同类加载单飞合并。

- **5 万提交时内存 248 MB**:主要来自 libgit2 遍历历史时的对象缓存与 macOS 分配器不归还的峰值内存,
  历史数据本身按结构估算约 15 MB(未单独测量)。`NO_CACHE=1 cargo run -p gitcore --release --example bench_load -- <仓库>` 关闭缓存后
  加载后 RSS 从 98 MB 降到 51 MB,但 history 变慢约 30%(587 → 757 ms)。第 5 步再权衡,候选方案:
  限制缓存大小、首屏先加载前几千个提交、读路径换 gix。
- **history 587 ms**:libgit2 拓扑排序需要遍历全部提交后才能输出。`git log --topo-order` 同样约 0.5 s,
  有 commit-graph 时约 0.28 s。候选方案:先按时间顺序快速显示首屏,后台完成拓扑排序后替换。

成功标准(方案中的建议目标,用实测校准):冷启动到可操作 < 1 s;5 万提交滚动 60 fps;常用操作界面响应 < 100 ms;空闲内存 < 150 MB。
